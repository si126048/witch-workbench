# 夜幕工作台架构

底板：Vangard Studio，提交 `fa3999a977b7f374df75962d6da3a0cbe42a3810`。
完整 Git 历史使用 partial clone 保留；GitHub pack 传输失败后，以同一提交的官方 codeload 归档补齐工作区和本地 blob。上游远端为 upstream，push URL 为 DISABLED。

## 边界

React 负责编辑和展示；演出领域模块负责版本化文档、确定性生成与校验；Electron 服务负责文件事务、Git/LFS 和 Ren’Py 子进程。系统操作不通过 shell 字符串执行。沿用上游 Worker 解析和写前日志事务。

每个游戏项目是独立 Git 仓库。共享内容是剧本、素材、演出文档和生成脚本；本机偏好、恢复数据、缓存、SDK、凭据不进入游戏仓库。应用源码仓库与游戏仓库分离。

## 演出契约

一个场景对应一个带版本号的 SceneDocument。场景、图层和对白使用稳定 ID；资源路径相对于游戏项目。文档与生成的独立 .rpy 文件成对保存、成对提交。手写 ATL 不做有损反向转换。写入前比较磁盘版本；冲突保留双方内容，用户审阅后才覆盖。

编辑器预览用于快速排演，Ren’Py 实机为最终效果依据。

保存时在每个项目的事务锁内再次检查磁盘摘要，防止检查与实际写入之间发生外部修改。JSON 和脚本由同一写前日志事务写入；恢复与写入共用该锁。提交前同时检查工作树和暂存区中的文档/脚本配对，禁止只提交一半或提交不一致版本。本机恢复草稿位于应用配置目录，与共享文件分离。场景文档撤销历史有界，切换文档时重置。

## 团队契约

每人一个本地副本、一个任务分支，通过托管平台 Pull Request 审阅。Git 凭据由系统管理。普通文本使用 Git，二进制使用 LFS。默认 fetch 加快进，分叉进入显式合并；不自动强推、rebase 或丢弃修改。网络失败不阻塞本地保存与提交。

场景分工依靠负责人约定和审阅；只有支持 LFS locking 的远端才提供二进制锁，不把锁表现成场景互斥保证。

## 发布

独立应用标识与配置目录；首版手动更新、未签名 Windows 安装包。保留 AGPL-3.0-only 与上游版权。所有生产可用声明须有对应验收记录。

`bootstrap.cjs` 同步设置应用名称、配置目录与协议权限，再加载主进程 ESM，避免异步模块加载越过 Electron ready 时机。启动错误写入个人配置目录的 `logs/startup.log`。

Windows 构建使用 `node scripts/build-windows.js`。构建前后校验运行时源码指纹；打包完成后逐一对比 ASAR 中系统服务文件与源码字节，并执行 JavaScript 语法检查，防止打包过程中修改源文件造成混合产物。构建期间不得编辑运行时源文件。验收同时比对安装前后 ASAR 摘要，检查安装版实际启动和卸载。

## 团队启动（0.2.0）

`teamOnboarding.js` 维护仅含名称、仓库地址、默认分支和推荐 SDK 版本的版本化团队配置；拒绝 URL 凭据、令牌参数、控制字符和可执行命令字段。负责人配置仓库时保留已有 origin，不隐式覆盖，不创建嵌套仓库；Git URL 重写情况下比较原始配置值。

`teamHubService.js` 提供受信渲染器和已授权项目目录范围内的系统操作。导入配置、导出 ZIP、选择安装包和创建快捷方式均使用原生文件对话框。加入包可包含负责人选择的安装程序与 SHA-256；启动脚本检查最低工作台版本和安装包摘要，再启动应用。成员认证交给系统 Git，Git/LFS 缺失时引导安装。

个人启动记录位于 `%APPDATA%/nightfall-workbench/team-launch`，包含该成员的本地目录，和便携团队配置分开。快捷方式使用 `--team` 指向个人记录，启动后仅 fetch 并打开本地项目，网络错误降级为离线工作。有未保存编辑时阻止自动项目切换。

主进程持有单实例锁，第二实例通过 Electron `additionalData` 转交启动请求，避免 Chromium 重排 argv 导致文件路径与开关混淆。安装版快捷方式指向安装的可执行文件；源码开发模式同时传入 bootstrap 入口。
