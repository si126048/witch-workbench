# 夜幕工作台使用说明书

适用版本：0.2.0，Windows 本地版。工作台用于 Ren’Py 剧本、素材与场景演出制作；团队通过 Git 和 Git LFS 异步协作，无须部署专用后端。新版增加负责人建队、成员加入包和日常启动快捷方式，详见第 11 节。

## 1. 安装与首次启动

1. 运行交付目录中的 `Nightfall_Workbench_Windows_0.2.0.exe`，选择安装位置，通过开始菜单启动“夜幕工作台”。普通使用不需要安装 Node.js 或 Python。
2. 需要团队同步时安装 [Git for Windows](https://git-scm.com/downloads/win) 和 [Git LFS](https://git-lfs.com/)。安装完成后重新启动工作台，使其读取新的环境变量。
3. 需要运行游戏时，另行下载并解压 [Ren’Py SDK](https://www.renpy.org/release/8.5.3)。本版验收使用 8.5.3；SDK 不包含在工作台安装包中。
4. 打开设置，选择 Ren’Py SDK 的目录。使用主工具栏的运行、停止按钮进行实机预览。

本版采用手动升级。安装包未签名；请从项目负责人提供的可信位置获取，并与随附 SHA-256 校验值核对。

## 2. 团队成员怎样获得工作台

工作台程序和游戏工程是两份独立内容：安装工作台不会自动获得游戏素材，克隆游戏仓库也不会自动安装工作台。

负责人向团队分发同一版本的安装包、此说明书、校验值，以及对应版本的源码和许可证。可使用团队网盘、NAS 的只读软件目录，或你们自己应用源码仓库的 Releases 页面。当前交付不会自动上传到互联网，也没有公共下载地址。

成员依次完成：下载并核验安装包 → 安装工作台 → 安装 Git/LFS → 配置仓库访问权限 → 在首页克隆游戏仓库 → 配置 Ren’Py SDK → 运行样片或团队场景。

源码基于 AGPL-3.0-only 的 Vangard Studio。分发工作台时保留上游声明与 LICENSE，并一同提供此版本的对应源码；不要只转发安装程序而丢掉随附材料。

升级时先提交或保存制作中的内容，退出应用，再安装负责人分发的新版本。团队应尽量保持相同工作台和 SDK 版本。安装位置与个人配置目录分开，个人配置保存在 `%APPDATA%/nightfall-workbench`。

## 3. 打开、创建与克隆游戏项目

- 本地项目：在首页选择“Open Project / 打开项目”，选择包含 `game` 目录的项目根目录。
- 新游戏：使用“New Project / 新建项目”向导建立 Ren’Py 工程，再导入角色和素材。
- 团队项目：点击“克隆团队项目”，输入 HTTPS 或 SSH 仓库地址，选择一个空文件夹。不要把密码或令牌写入仓库地址。
- 演出样片：解压交付的样片压缩包，用工作台打开解压后的项目根目录。样片包含原创程序绘制背景、角色和合成音频，用于验证制作流程。

克隆认证使用系统 Git 凭据管理器或已配置的 SSH。私有仓库需要负责人先邀请成员并授予访问权限。克隆失败时错误显示在对话框中；保留失败目录以便检查，重试请选择另一个空文件夹或自行检查原目录。

## 4. 界面入口

主编辑器保留剧本、剧情关系图、角色、素材、诊断和设置等功能。左侧定位文件，中间编辑，右侧管理故事元素与素材。

点击顶部“制作工作台”进入专用页面：

- **团队同步**：工作区变更、差异、提交、分支及同步操作。
- **场景演出**：图层、舞台、属性、关键帧以及对白和音频事件。
- **返回编辑器**：回到剧本与素材编辑界面。有未保存的演出时会提示处理。

制作页面使用统一的深色面板和 SVG 图标。部分继承的高级工具仍保留英文术语。

## 5. 制作一个场景

1. 先将图片放在 `game/images`，将音乐和音效放在 `game/audio`。也可以用主编辑器的素材工具导入。
2. 进入“场景演出”，选择已有场景，或在当前场景保存后点击“新建场景”。场景有稳定 ID，标题可以修改。
3. 添加图层时输入项目相对路径，例如 `game/images/street.png`。选中图层，在右侧编辑资源、层级及关键帧属性。
4. 每个图层从 0 秒开始。水平与垂直中心通常使用 0～1 的相对坐标；0.5 表示舞台中心。透明度范围为 0～1，缩放 1 表示原始尺寸。
5. 拖动时间游标，在目标时刻添加关键帧，再修改位置、缩放、旋转或透明度。相邻关键帧使用线性插值。
6. 展开底部“对白、转场与音频事件”，添加或修改对白、说话人、音乐、音效和淡入转场及其时间。
7. 点击“审阅生成差异”，比较原脚本与将要生成的脚本，确认后“成对保存”。
8. 返回主编辑器，用 Ren’Py 运行游戏进行最终检查。

文档位于 `.nightfall/scenes/<场景ID>.json`，生成脚本位于 `game/nightfall_generated/<场景ID>.rpy`。在手写剧本中使用 `call nf_<场景ID>` 播放该场景，例如 `call nf_opening`。

编辑器舞台是快速预览，当前不播放音频。游戏中的对白等待用户阅读，后续提示时间会随阅读等待延后；最终音画效果以 Ren’Py 实机为准。演出文档与生成脚本须一同提交。手写 ATL 不会自动反向还原到可视化编辑器中。

舞台播放控制旁的箭头用于撤销和重做，最多保留当前场景的 100 次文档编辑。在未聚焦输入框时，也可使用 `Ctrl+Z` 撤销、`Ctrl+Y` 或 `Ctrl+Shift+Z` 重做；输入框内使用浏览器自身的文本撤销。切换场景会清空该编辑历史，保存不会替代 Git 提交。

## 6. 开始团队协作

推荐每人一个工作副本，每个场景或任务一个分支。成员不要同时在网盘同步的同一个工作目录内制作。

首次使用 Git，成员在终端设置自己的提交身份：

```powershell
git config --global user.name "你的名字"
git config --global user.email "你的提交邮箱"
git lfs install
```

负责人在 GitHub 等平台创建游戏仓库并邀请成员。已有项目可先在团队同步页初始化 Git，再在终端为其配置远端；下例地址须替换成你们自己的仓库：

```powershell
git remote add origin https://github.com/你的团队/游戏仓库.git
```

打开“仓库管理 → 配置 Git LFS”，审阅 `.gitattributes`、`.gitignore` 以及已有二进制文件列表，再应用规则。此操作不重写历史。已有素材请与规则文件一同审阅并提交，使新提交中的素材通过 LFS 保存。

日常流程：

1. 开始工作前获取远端，并快进拉取。
2. 创建任务分支，例如 `scene/prologue`。
3. 编辑自己的场景、保存剧本和演出。
4. 在变更列表查看差异，勾选此次修改的文件，填写提交说明并提交。
5. 推送分支，在仓库托管平台创建 Pull Request，邀请同伴审阅。
6. 通过审阅后由负责人合并。合并后成员更新自己的工作副本。

在编辑器有未保存内容时，工作台会阻止提交及会影响工作区的同步操作。先返回编辑器全部保存，场景演出则需要审阅后成对保存。

## 7. 同步、冲突与文件锁

“获取远端”更新远端状态，不合并内容；待推送、待拉取数量反映最近一次获取时的状态。

“快进拉取”只允许快进更新。若双方都有新提交，会拒绝自动处理。确认本地内容已提交，再使用“仓库管理”中的显式合并操作。

发生文本冲突时，点击冲突文件查看共同基线、本地和远端版本。编辑完整解决内容，删除冲突标记，保存并标记解决，再审阅和提交。不会自动选择一方覆盖另一方。

演出文档发生冲突时，不要手工拼接不熟悉的关键帧数组。先保留一个完整、有效的文档版本，再在场景演出页比较磁盘版本、重新打开并生成脚本。文档和脚本一致后才能提交。

二进制冲突应先在团队内确认采用哪个素材版本，在外部完成文件替换后再提交，不要把图片当作文本合并。

LFS 锁取决于远端服务是否提供 locking 接口；无法查询或锁定时会显示失败原因。锁功能不等于场景互斥，也不能代替分工约定。不要对别人的工作强制解锁。本版不提供自动 rebase、强推或自动丢弃本地修改。

## 8. 保存与恢复

场景保存会同时检查文档与生成脚本的磁盘版本。如果外部程序或同伴同步改变了文件，保存将被阻止。使用“比较磁盘版本”查看双方内容；可以保留当前编辑，或明确丢弃后重新打开磁盘版本。

有效的演出编辑会在本机配置目录保存恢复草稿。重新进入场景时可以恢复或丢弃草稿；恢复旧基线不会绕过磁盘冲突检查。最后一次编辑到草稿写入之间有短暂间隔，自动恢复不能代替主动保存。

主编辑器也保留上游自动恢复机制。多文件保存使用写前日志恢复；失败时不要自行删除保存日志，先保留项目副本并查看错误信息。

## 9. 常见问题

| 现象 | 处理 |
|---|---|
| 检测不到 Git/LFS | 安装后完全退出并重启工作台，检查终端 `git --version`、`git lfs version` |
| 私有仓库认证失败 | 确认成员权限与系统 Git 凭据或 SSH 配置，先在终端验证访问 |
| 推送失败 | 本地提交仍保留。检查网络、权限和远端状态后重试，不要重置工作区 |
| 看不到素材 | 确认使用项目相对路径、文件已下载，检查是否遗漏 `git lfs pull` |
| 无法运行游戏 | 设置正确 SDK 路径，查看 Ren’Py 错误日志；优先使用验收版本 8.5.3 |
| 不能提交演出 | 同时选择演出 JSON 与对应生成 `.rpy`，先重新生成并保存一致内容 |
| 无法创建分支或拉取 | 先处理未提交修改；工作台不会代替你丢弃文件 |

## 10. 分发前检查

负责人分发同一版本安装包、对应源码、许可证、说明书和校验文件，并发送游戏仓库地址及邀请。安排一名成员在自己的电脑上验证安装、克隆、LFS 素材下载、配置 SDK、运行样片和推送任务分支，再让全队开始制作。

本机验收记录单独随交付提供。远端平台权限、锁支持和成员电脑环境需要在你们真实团队仓库上确认。

## 11. 团队协作一键启动

首页“团队协作启动”或工具栏的分支 SVG 图标打开三个入口。

**负责人建队**：先在 GitHub 等平台创建游戏仓库并邀请成员，然后打开本地游戏项目，填写团队名称、仓库地址、默认分支和 SDK 版本，点击“配置当前游戏仓库”。若提示有未保存内容，可在向导内点击“保存剧本与项目设置”，包括首次生成的项目布局；场景演出仍须返回演出页审阅保存。未初始化的目录会初始化 Git；已有 origin 与填写地址不一致时会拒绝覆盖。到团队同步页审阅 Git LFS 规则、提交并推送初始游戏内容。空远端尚无默认分支时，成员无法克隆；应先完成首次推送。

点击“生成成员加入包”，默认可以选择并附带交付的 0.2.0 安装包。生成的 ZIP 包含团队配置、启动脚本和安装程序校验值，不包含密码、令牌、游戏素材或你本机的项目路径。将完整 ZIP 发给成员；保留 AGPL 对应源码与许可证的分发渠道。安装包由负责人选择，请使用本次交付的正确版本。

**成员首次加入**：解压整个 ZIP，双击“加入团队.cmd”。尚未安装工作台且包中带有安装程序时，先完成安装向导，并保留默认的开始菜单快捷方式。启动脚本随后打开工作台并填入团队配置。若已有版本过旧，请先升级到 0.2.0。也可直接在工作台“成员首次加入”中导入 `team.nightfall-team.json`。

工作台显示 Git、Git LFS 和 SDK 状态。缺少 Git/LFS 时打开官方下载页安装，再完全退出并重新启动工作台。私有仓库须先有成员权限，并通过系统 Git 凭据或 SSH 认证；不把令牌写进配置。点击“选择目录并加入团队”，选择空文件夹，自动克隆默认分支和 LFS 素材。失败不会覆盖现有目录，按错误原因处理后使用新的空目录重试。

克隆后可填写提交姓名和邮箱，点击“保存该副本的身份”；这只修改当前工作副本的 Git 配置。选择单独解压的 Ren’Py SDK，并按团队推荐版本使用。

**日常开工**：点击“创建日常快捷方式”，选择保存到桌面。之后双击快捷方式即可获取远端状态并打开本地工作副本，不再填写地址。快捷方式指向个人配置目录中的启动记录，不能作为别人的加入包。程序已运行时，会把请求交给现有实例；有未保存编辑时会阻止切换。

日常启动只执行 fetch，不自动 pull、merge、rebase 或丢弃修改；待拉取内容由团队同步页审阅处理。网络失败仍打开本地副本并显示离线原因。换了电脑或移动项目目录后，重新打开项目并创建新的快捷方式。

“一键”指准备完成后省去重复定位、填写和打开项目。首次账号认证、选择空目录、安装依赖和接受安装向导仍需要成员本人操作；无需架设专用后端。
